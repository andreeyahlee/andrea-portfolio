### Type scale — standardized site-wide, 2026-07-27
Ran a full typography standardization pass across all 7 pages (index, works, about, side-quests, and the 3 case studies) — font-family/weight/size/line-height/letter-spacing only, no layout properties touched. Key decisions (all direct user instructions, not inferred):

- **Poiret One replaces Lora as `--font-display` everywhere**, not just the homepage. Every page's `:root` token was changed; individual heading rules still reference `var(--font-display)` (never a hardcoded `'Lora'` string), so the swap cascades automatically. The 2026-07-19 "homepage exception" note above is now obsolete — Poiret One is the site's one display font.
- **Body copy is now fluid** (`clamp()`-based), not fixed-px at every breakpoint like it was before. Standard tiers in use: Body/Base `clamp(0.9375rem, 1vw, 1.0625rem)` / line-height 1.47; Caption `clamp(0.75rem, 0.7vw, 0.8125rem)` / line-height 1.35.
- **Heading tiers**: H1/Hero `clamp(1.75rem, 3.6vw, 3.25rem)` / 1.1 / -0.03em (hero headings, `.contact__heading`); H2/Section `clamp(1.75rem, 3vw, 2.5rem)` / 1.2 / -0.025em (case-study section heads — this replaced many headings that were previously frozen at a fixed 40px with zero responsive scaling, `seletar.html` especially); H3/Bold `clamp(1.125rem, 1.6vw, 1.375rem)` / 1.33 / -0.01em weight 700 (card/finding titles); H3/Medium — same size, weight 500, normal letter-spacing (subtitles/attributions). Two Gochi Hand tiers: Hand/Section `clamp(1.5rem, 2.2vw, 2.1875rem)` / lh 1 (mid-size handwritten accents, was fixed 32-35px), Hand/Card `clamp(1.375rem, 2vw, 1.75rem)` / lh 1 (small grid-card names like `.sq-card__name`). `Display/LG` (32px fixed, card titles) is unchanged in size — it's a separate, locked tier.
- **Tags/labels use two tiers by role**: Tag/Eyebrow (`.t-label` and equivalents) stays DM Mono 700 11px / letter-spacing 0.6em — big section-level tags. Tag/Pill (badges, pills, inline category labels) is DM Sans 600/700, `clamp(0.6875rem, 0.6vw, 0.8125rem)`, letter-spacing 0.14em, uppercase — this consolidated five different letter-spacing values (0.6em/0.14em/0.1em/0.08em/0.04em) that had accumulated with no clear pattern.
- **`.t-label` font-family bug fixed**: `seletar.html` and `pethaus.html` had it on DM Sans instead of DM Mono like the other 5 pages — now consistent everywhere.
- **Excluded from this pass** (left exactly as they were): `pethaus.html`'s scaled-down mock-browser widget (`.bd-*` classes, deliberately tiny pre-scale px values inside a `transform: scale(...)` wrapper) and its client-brand-showcase literals (`.ph-vtag` `'Inter'`, `.ph-visual-type__sample--serif` `'Playfair Display'` — these depict PawHaus's own brand fonts as content, not this site's chrome).
- Also cleaned up: `side-quests.html` had a whole dead CSS block (`.pd-grid`, `.card__case-title` etc.) left over from when that page was built by copying `works.html` and trimming its hero section — the HTML was removed at the time but the CSS wasn't; removed now since it had zero references left in the page.

## Dark / Light mode on case study pages
- **Dark mode** (default) = the case study's own `project/*` accent color as the page background (`project/seletar` #304c95 for seletar.html, etc.) — NOT the generic `--bg-dark`.
- **Light mode** = the shared site-wide light preset used on every other page: `--bg-light` (#f4f4eb) background, `--ink-dark` text, `#6b7a00` accent color for section labels/eyebrows, same nav/toggle treatment as index.html/about.html.
- The toggle button, cursor-flower swap, and compact tablet/mobile nav collapse (see below) are a locked cross-page component — copy the exact CSS/HTML/JS from `index.html` (source of truth), don't re-derive it. Every case study page must include the `.nav__toggle` button and a full `body.light-mode` override block; don't skip it when rebuilding a page from Figma.

**pethaus.html dark-mode fix, 2026-07-19:** this page was originally built entirely in a single light cream palette (`--paw: #ebeae0`) with text hardcoded to `var(--ink-dark)` everywhere — `body.light-mode` only swapped to an almost-identical `--bg-light` cream, so the page never actually had a working dark mode, unlike arvo.html/seletar.html. Fixed to conform to the standard above: `--paw` is now `#8c4d00` (dark rust, matching the homepage card color) and is the default page/nav/loader background; body copy now uses new adaptive tokens — `--text` (→ `ink-light` by default, `ink-dark` in `body.light-mode`) plus alpha variants `--text-75/-70/-60/-50` and border/hover tokens `--border`/`--hover-wash` — all flipped by `body.light-mode` reassigning the custom properties in one place, so don't add per-element `body.light-mode` overrides for body copy; use the `--text*` tokens instead.
  - **Do NOT blanket-replace `var(--ink-dark)`** in this file — many components (`.ph-pattern-card__inner`, `.ph-visual-type__card`, `.ph-visual-swatch`, `.ph-visual-kit__inner`, `.ph-comp-card__inner`, `.ph-tag`, `.ph-dark-card`, `.ph-landscape`, `.ph-persona__question`, `.ph-solution-move__card--dark`, `.ph-test-card-base`, `.ph-macbook`, `.ph-reflection-next__card`, all `.ph-vbtn--*`/`.ph-vtag--*` swatches) have their own fixed light or dark background baked into the case-study content design itself (independent of the page theme) and correctly keep hardcoded `ink-dark`/`ink-light` text — only text sitting directly on the adaptive `.section`/`--paw` background should use `--text*`. `.ph-visual-label` is reused in both contexts; the in-card instances carry an added `.ph-visual-label--fixed` modifier to force `ink-dark` — check for that pattern before assuming a class is uniformly adaptive.

**Mobile/tablet nav accordion, 2026-07-27:** at `≤1024px`, the hamburger's `.nav__mobile-menu` now mirrors the desktop Work/Play dropdowns instead of showing flat, non-functional "Work"/"Play" links — each is a tap-to-expand accordion row inside the mobile menu, listing the same submenu items as its desktop `#nav-work-menu`/`#nav-play-menu` counterpart. Implemented on all 7 pages; `index.html` is the source of truth to copy from (its `.nav__mobile-item`/`.nav__mobile-trigger`/`.nav__mobile-submenu` block).
- **Spacing**: `.nav__mobile-menu ul` padding is `16px` on all sides (was `0.625rem 0.5rem`), and `.nav.is-open .nav__mobile-menu` max-height raised from `200px` to `500px` to fit the expanded accordion content.
- **Structure**: each accordion row is `<li class="nav__mobile-item" id="mob-{work,play}-item">` wrapping a `.nav__mobile-trigger` (a `<button>` for "Work", an `<a href="...">` for "Play" — same button-vs-link distinction as the desktop dropdowns, since "Play" still needs to be a real navigable link to `side-quests.html`) plus a `.nav__mobile-submenu` of `<a>` links, toggled via `.nav__mobile-item.is-open`. JS is a generic `mobileDropdowns` array + `closeAllMobileDropdowns()` (mirrors the desktop `navDropdowns` pattern) so opening one row closes the other; for the "Play" `<a>` trigger, only the chevron SVG gets the toggle click-listener (`trigger.querySelector('.nav__work-chevron')`) so tapping the "Play" label still navigates.
- **CSS specificity gotcha (found and fixed same day)**: the pre-existing generic rule `.nav__mobile-menu li a` (1 class + 2 element-type selectors) has *higher* specificity than a bare `.nav__mobile-trigger` class selector, so it silently overrode the new trigger/submenu-link styles whenever the trigger was an `<a>` — this only broke "Play" (a `<button>`-based "Work" trigger isn't matched by `li a` at all), producing a squashed, non-right-aligned chevron. Fix: every accordion rule is scoped with the `.nav__mobile-item` ancestor class (`.nav__mobile-item .nav__mobile-trigger`, `.nav__mobile-item .nav__mobile-submenu a`, and their `:hover`/`body.light-mode` variants) — the extra class in the selector reliably wins regardless of tag type. Don't drop that ancestor scoping when copying this pattern to a new page.
- Work submenu items always list all 3 case studies (ARVO/Seletar Airport/Paw Haus) including a self-link on that same case-study page, matching the desktop `#nav-work-menu` pattern already established.

## Architecture
- Single-file-per-page static site: `index.html`, `works.html`, `about.html`, `side-quests.html`, `case-studies/{arvo,seletar,pethaus}.html` — each carries its own full inline `<style>` + `<script>` block, no shared CSS/JS file. Changing something site-wide (a design token, the nav, the footer) means editing all 7 files.
- Assets in `Asset/` folder
- Deployed via GitHub Pages from `github.com/andreeyahlee/andrea-portfolio`, branch `main`
- Deploy: `git push origin main` (Pages rebuilds in ~1–2 min)
